# Claims must be earned by results

Current status: no scientific claim has passed. The results CSV is an empty schema, not a partial result table.

| Candidate claim | Minimum supporting evidence | Mandatory competing explanation | Limit |
|---|---|---|---|
| Forked-future training improves learning efficiency | F03 vs F02 full learning curves under matched allocated GPU-hours, multiple seeds, same hidden future/query material | Benefit is merely more continuation data or reader queries | One objective/sampling comparison; no new general RL theorem |
| Improved memory retains update-relevant information | Fixed-reader gain under calibrated capacity, controls for parsing/extraction, retention/update/reader diagnostic cross-tabs | A strong event ledger or summary already solves it | Free text has uncertain evidence certification |
| Method handles changing future demand | Held-out target-age/operator-composition distributions, same prefix memories, independent worlds | Generator labels or entity IDs expose targets | Tested shifts only |
| Practical transfer | Untouched complete external tests plus independent natural chronological update examples | Synthetic benchmark overfitting or contaminated model checkpoint | Natural source/label limitations disclosed |
| Runtime accelerates the intended computation | Fixed-trace state/logprob/gradient parity, strong optimized baseline, end-to-end timings and time to dev quality | Standard engine batching/cache option explains speedup | Hardware/model/workload range actually measured |
| Adaptive continuation allocation is beneficial (optional) | Exact importance-weight expectation tests, uniform/full-pool controls, overhead-inclusive time-to-quality | Biased selection or altered target distribution | Separate protocol; not primary F03 |

Do not claim the first update-sufficiency problem, first memory RL, first branching estimator, first evidence audit, first prefix cache, or first temporal benchmark. The novelty matrix lists direct predecessors. A reference proof or correct software implementation can be essential without being a new research contribution.

For every paper sentence containing “improves,” “outperforms,” “efficient,” “robust,” “generalizes,” or “novel,” link a concrete contrast and its uncertainty/limitations. Avoid replacing this exercise with broad rhetorical claims. Include negative results and disclose changed protocols. Acceptance remains a reviewer decision; no artifact here guarantees publication.
